# Agent Note: Community desktop identity and attribution

Status: implemented
Archived: 2026-09-02

English | [中文](2026-08-26-community-desktop-identity-and-attribution.zh.md)

## Problem

The community macOS wrapper packages the official DeepSeek Harness runtime, but using the complete upstream product name, bundle namespace, and Web favicon as the desktop application's own identity can imply that the wrapper is an official DeepSeek distribution. Keeping the upstream MIT license only inside application resources also makes attribution difficult to find before installation. Starting `dsh web` without suppressing its ordinary browser launch can expose the private loopback URL in a second, unintended window even though WKWebView owns the desktop presentation.

## Decision

This decision supersedes only the visible product-name and icon choice in the [native macOS desktop distribution](../feature/2026-08-17-native-macos-desktop-app.md). The community application is named `DSH Desktop`. `DeepSeek Harness` appears in descriptive text such as “built on DeepSeek Harness” and beside the exact embedded runtime version, not as the wrapper's standalone product name. The App uses the neutral `io.github.eddieewei.dshdesktop` bundle identifier and an original terminal-style icon generated by the macOS build. Upstream package names, CLI commands, data directories, settings, session formats, plugins, permissions, and agent behavior remain unchanged.

Attribution is visible before and after installation. The repository landing page identifies the independent fork and links the upstream repository. `apps/macos/ATTRIBUTION.txt` states that DSH Desktop is not sponsored, endorsed, or approved by DeepSeek, identifies the upstream source and copyright owner, and points to the included license texts. The App metadata and Help menu expose the independent name, upstream URL, and packaged notice. The App resources and DMG both include the DeepSeek Harness MIT license; third-party and Node.js notices remain inside the App.

The native launcher and packaged-runtime smoke both pass `--no-open` while retaining `127.0.0.1` and an OS-assigned port. WKWebView remains the only automatic presentation for that private origin. The per-launch token, authenticated cookie bootstrap, origin restriction, and non-persistent WebKit store remain unchanged.

## Alternatives considered

**Keep `DeepSeek Harness` as the App name and add only a disclaimer.** Rejected because a disclaimer does not remove the product-name, bundle-namespace, and icon combination that can create source confusion before the notice is read.

**Remove every DeepSeek Harness reference.** Rejected because truthful source attribution, license compliance, reproducibility, and the embedded kernel version all require the upstream name.

**Replace loopback HTTP with a desktop-private IPC protocol.** Rejected because the authenticated loopback composition already carries the native Harness client without forking its transport or agent runtime. The unwanted system-browser launch is removed by `--no-open`.

## Consequences

Users can distinguish the community desktop wrapper from its embedded upstream runtime while still identifying the exact Harness version and source. The generated icon and neutral bundle identifier avoid reusing the upstream application's visual or namespace identity. Attribution and license texts travel with every DMG and remain accessible through the installed App. The application still logs and stores Harness-owned runtime data in the established DSH locations; only desktop-wrapper logs use the DSH Desktop name. Maintainers must preserve the independent identity and notices when release packaging changes.
