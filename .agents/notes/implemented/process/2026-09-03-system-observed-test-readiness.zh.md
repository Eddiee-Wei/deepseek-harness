# Agent Note：集成测试使用系统实际观测的就绪状态

状态：已实现

[English](2026-09-03-system-observed-test-readiness.md) | 中文

## 问题

三个集成测试将调用方动作视为另一个系统边界已经完成的证明。在测试整体负载较高时，Inspector 测试会在浏览器 realm 处理 Console enable 帧之前发出 Client Console 值，spill 清理测试会将请求写入的时间戳与文件系统保存的时间戳比较，而 HMR 测试会在注册后立即创建受监视的路径结构并依赖原生 watcher 事件投递。每项断言描述的产品行为都成立，但测试准备过程没有建立断言所依赖的状态。

## 决策

测试通过拥有被观测状态的系统确认就绪：

- Inspector Console 测试在发出 Console 值之前，通过同一条有序 Client 传输完成后续且无副作用的 Runtime 请求。请求响应证明每个 DevTools session 对应的 Console enable 帧均已处理。
- spill 清理边界测试在 `utimesSync` 之后读取文件实际保存的 `mtimeMs`，并将该观测值作为清理 cutoff。测试因此使用文件系统可表达的时间戳验证严格的 `mtimeMs < cutoffMs` 规则。
- HMR 失败传播测试以已存在的配置文件启动，使 Chokidar 的 ready 生命周期负责初始通知。缺失父目录的验收场景使用轮询，因为它验证的是新目录上的 watch-root 发现能力，而不是原生文件系统事件队列的时序。

这些修改没有添加重试、扩大超时时间、放宽断言或改变产品行为。

## 考虑过的替代方案

**增加测试超时时间。** 未采用，因为订阅建立前发出的事件或原生 watcher 遗漏的事件不会因预算增加而出现。

**重复写入直到断言通过。** 未采用，因为重复刺激会掩盖一次具备因果顺序的操作能否产生所需观测。

**对请求写入的 spill 时间戳进行舍入。** 未采用，因为文件系统精度不同；直接读取保存后的元数据才能用文件系统自身的表示方式定义边界。

## 结果

这些测试保留原有行为断言，同时移除了调度时序和时间戳表示假设。后续失败将指向有序传输、清理比较或 HMR watch-root 路径故障，而不是主机负载或文件系统精度。
